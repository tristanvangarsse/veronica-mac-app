## Automated checks

All 56 regression scripts passed against the final source and frozen engine. Coverage includes real image/video/audio processing, embedded dates, independent folder recipes, staged-output verification, exact-original rollback, guarded review decisions, cancellation/recovery, source identity changes, filename conflicts, persistent logs, offline clean-install dependency isolation, and release integrity.

New checks exercise the actual Swift models for 38 review reasons, including combined video risks and unknown reasons, and verify that UI approval availability matches the engine. Read-only and unavailable libraries preserve source bytes; verified recovery originals are releasable through the usual originals-to-Trash path. Modified or unrecognized recovery files still block disposal. Conversion extensions match the actual format even when name/date standardization is disabled. Empty or unreadable media does not offer date editing.

The application and nested code passed strict signature, source/runtime/tool provenance, minimum-system-version and installer checks. The third-party source archive matches the same Python packages, date editor, media tools and normalized tool provenance as this build.

A clean GitHub build exposed the newer Homebrew ExifTool shell-launcher layout. The packaging helper now handles both that layout and older directly patched Perl programs. Its new regression executes the relocated program after removing the build prefix and rejects unknown launchers. On the release machine it produces byte-identical date-editor files, so the tested app and installer remain unchanged.

## Evidence boundaries and beta limitations

The earlier build-9 stress test completed a 3,000-file mixed-library run, verified recoverable originals and performed a fresh-session repeat cleanup with zero further changes. Its abrupt-termination test retained all 24 original hashes and completed after restart. Those are earlier-build evidence; the complete 3,000-file workload was not repeated for build 11. Current recovery and format changes have focused source/frozen-engine checks and the native workflow above.

Each new launch scans afresh. Already optimized files can appear as candidates again; replacements are only installed if they pass verification and meet the folder's saving targets. In the repeat native test, every output byte remained unchanged. Large-library performance and more codec/storage combinations remain useful beta feedback.

This is one physical Mac. No claim is made for Intel, older macOS releases, another physical Mac or indefinite compatibility with future systems. The first-download Gatekeeper approval was not repeated in this temporary-profile test. Offline dependency denial is covered by the clean-install regression. Processing uses generated copies; broader real-library testing belongs to the public beta and should begin with disposable copies and backups.
